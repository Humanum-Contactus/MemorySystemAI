# Proposition de nommage — Sensors&MemorySystemAI

## Pourquoi faire évoluer le nom ?

**MemorySystemAI** met l’accent sur la mémoire (juste, central).  
Or la finalité du projet n’est pas une base de faits : c’est un **système
sensoriel + mémoire émotionnelle** qui relie le monde à la décision.

Sans le volet **Sensors**, on retombe mentalement dans :

- un index JSON + un LLM qui « parle dessus »
- des règles texte déguisées

Avec **Sensors**, on annonce le vrai objet :

> percevoir → évaluer (exposant) → mémoriser → injecter / inhiber → agir

Le prototype `memory-node` (juillet 2026) a rendu ça tangible : caméra, micro,
haut-parleur, nursery, et mémoire qui répond **sans** repasser par le LLM
quand le fait est déjà appris.

## Proposition

**Sensors&MemorySystemAI** (SMSAI en abrégé interne)

| Partie | Signifie |
|--------|----------|
| Sensors | Capteurs / canaux V O T G Od I C + outils physiques |
| Memory | Exposants, états P/N/X, inhibition apprise |
| SystemAI | Architecture de boucle, pas « un modèle de plus » |

Le dépôt GitHub peut garder l’URL historique `MemorySystemAI` tout en
affichant le nom long dans README / whitepaper v2.

## Variantes

- `SensorMemoryAI` — plus court  
- `Sensory-Emotional Memory System` — formulation papier
